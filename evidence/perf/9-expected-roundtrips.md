2. **多くの遷移が3回に届くのは、D-07（キャッシュ）が効いた2回目以降の見込みだけ。** ただし、S-64・I-211 が「キャッシュなし（初回）」と「キャッシュあり（2回目以降）」のどちらで数えるかは、仕様に書かれていない（5. の確認事項1）。

4. **「部活の管理」（⑥）は上限5**だが、D-06＋D-08（標準）で7（幹事・運営者とも）。最大削減（4）なら届く。D-07命中では0。

## 2. 読み方と見込みの出し方

### 2.1 前提（数え方は SP-82 のとおり）

- 往復は、読取の Supabase への HTTP 1往復。**サイドバー込みの合計**。書込み（action_logs の insert、既読化 update）は読取に含めない。
- 現状の値は 8-baseline-counts.md の値（偽repo、規模は小／大。「検索条件なし」の下限）。**本番規模は未確認**。
- 遷移1回は再実行2回（サイドバーのボタンを押す遷移では、1回目はサイドバー分のみ。画面内のボタンを押す遷移では、1回目に**押した画面の描画**も走る。⑧〜⑭がこれにあたる）。このため、画面内ボタンの遷移の合計は「サイドバー分＋元の画面の画面分＋移動先の画面分」になる。
- Cloud の実行場所（米国・変更不可）と Supabase（東京）は前提。往復の**時間**は本書の対象外（時間は T0e・T5）。
