## 所見

1. **サイドバーが固定コスト**: 全再実行で 3 往復（count_unread / get_role / is_organizer）。遷移は2回の再実行なので画面と無関係に 6 往復。未読件数・権限を `session_state` に持てば減らせる候補。
2. **N+1 が5画面にある**: home、employee_search、club_detail、messages、employee_profile、club_admin。件数に比例して往復が増えるため、データが増える運用日が一番遅くなる形。
3. **同じ表を同じ描画で複数回引く**: employee_search は `clubs_repo.search({})` 系を画面とサービスで2回、`messages（幹事）` と `club_admin` は `is_organizer`／`get_role` を重ねて呼ぶ。
4. **ウィジェット操作1回が全再実行**: home のラジオ切替で 23 往復（大）がやり直し。`st.cache_*` は0件。
5. **表示時の書込み**: club_search（検索）・club_detail（閲覧）が action_logs、messages が既読化を実行する。往復の数に加えて書込み1往復が表示の中に入る。今回は実行していないので時間は不明。
6. 改善の候補（実装はしない。DB時間が測れてから効果を比べる）: サイドバー値の保持、`st.cache_data(ttl=…)`、`in_()`／埋め込み select による一括取得、人気部活の集計のDB側化。
