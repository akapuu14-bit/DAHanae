## 0. 守ること（1Aの学びと今回の制約）

1. **計測タブは Claude in Chrome（`tabs_create_mcp`）で作ったタブを使う。** 人間が別に開いたタブは自動操作できない。人間はそのタブの上でログインする。
2. **Chrome ウィンドウがターミナル等に覆われると `visibilityState=hidden` になり測れない。** 計測前と計測中に JS で `visible` を確認し、`hidden` の回は破棄して記録する（SP-81⑤）。人間にウィンドウを最前面に保ってもらう。画面スリープもさせない。
3. **共通パスワードは記録・ログ・スクショのどこにも残さない。ログインは人間が行う。** kurosu はパスワードを入力しない・受け取らない・書かない。
4. **人間が画面を見ている間だけ操作する。** 各区切りの最初に、人間が見ていることを確認してから始める。人間が席を外したら、そこで止める。
5. **ブラウザを無人で自律操作させる段取りは作らない。** ページ内で自動クリックを回し続けるループは使わない。人に手でスクリプトを実行させる段取りも作らない。**1遷移ごとに、通常のツール呼び出し（`javascript_tool`）を1回行い、その1回でクリック1回・計測1回だけを行う。**
6. **スクショを撮らない。** `computer` の screenshot、`read_page`、`get_page_text` など大きい出力を返すツールは使わない。時間は JS が返す1行のテキストだけを読む。
7. **書込みを伴う操作は計測しない・行わない**（申込、メッセージ送信、キャンセル、確認スタンプ、プロフィール保存、部活情報・開催・メンバーの保存や追加、ログアウト）。通知画面を開くと既読化の書込みが起きる（アプリの仕様。計測対象の④）。これは避けられない。
8. `app/` と本番のデータは変更しない。実DB操作もしない。

## 3. 時間読み取り用の JS

遷移開始〜描画完了のミリ秒を返すだけの短い関数。**登録は1回の呼び出し**、計測は**呼び出し1回につきクリック1回**。返り値は1行の文字列（`ID|結果|ms|見出し`）。

### 3-1 登録（タブごとに1回。リロードで消える）

```js
(() => {
  const d = () => document.querySelector('iframe[title="streamlitApp"]').contentDocument;
  const sleep = ms => new Promise(r => setTimeout(r, ms));
  const h1 = () => [...d().querySelectorAll('h1')].map(h => h.innerText).join('|');
  const side = l => b => b.closest('[data-testid="stSidebar"]') && b.innerText.trim().startsWith(l);
  const main = l => b => !b.closest('[data-testid="stSidebar"]') && b.innerText.trim() === l;
  const btns = () => [...d().querySelectorAll('button')];
  const nth = (f, n = 0) => () => btns().filter(f)[n];
  const notif = t => () => btns().find(b => {
    if (!main('見る')(b)) return false;
    let e = b; while (e && !e.innerText.includes('【')) e = e.parentElement;
    return !!e && e.innerText.includes('【' + t + '】');
  });
  const F = {
    '1': nth(side('部活を探す')), '2': nth(side('人を探す')), '3': nth(side('メッセージ')),
    '4': nth(side('通知')), '5': nth(side('自分のプロフィール')), '6': nth(side('部活の管理')),
    '7': nth(side('ホーム')),
    '8': nth(main('詳しく見る')), '9': nth(main('← 戻る')), 'back': nth(main('← 戻る')), '13': nth(main('← 戻る')),
    '10': nth(main('プロフィールを見る')), '12': nth(main('プロフィールを見る')),
    '11': () => [...d().querySelectorAll('details button')].find(b => !b.closest('[data-testid="stSidebar"]') && /（.+）/.test(b.innerText)),
  };
  window.__T0E = {
    chk: (id, arg) => { const el = (id === '14' ? notif(arg || 'メッセージ') : F[id])(); return id + '|' + (el ? 'found' : 'none') + '|' + document.visibilityState + '|' + h1(); },
    run: async (id, arg) => {
      const el = (id === '14' ? notif(arg || 'メッセージ') : F[id])();
      if (document.visibilityState !== 'visible') return id + '|discard|hidden-before';
      if (!el) return id + '|none|no-element';
      const before = h1(); const t0 = performance.now(); el.click();
      let stable = 0;
      while (performance.now() - t0 < 20000) {
        if (document.visibilityState !== 'visible') return id + '|discard|hidden-during';
        await sleep(4);
        const running = !!d().querySelector('[data-testid="stStatusWidget"]');
        if (!running && h1() !== before) { if (++stable >= 3) return id + '|ok|' + Math.round(performance.now() - t0 - 12) + '|' + h1(); }
        else stable = 0;
      }
      return id + '|timeout|20000|' + h1();
    },
  };
  return 'registered|' + document.visibilityState;
})()
```

- `id` は遷移の番号（`'1'`〜`'14'`）。`'back'` は「← 戻る」を押す**計測しない**準備操作（結果の ms は記録しない）。
- 「ID|結果|ms|見出し」の結果は `ok`（有効）／`discard`（`hidden` のため破棄）／`none`（ボタンが無い）／`timeout`（20秒で安定しなかった）。
- `-12` は、3回安定の確認に要する約12msを引く補正（1Aと同じ式。比較のためそろえた）。
- **このセレクタ（`details button`、`stSidebar`、`stStatusWidget`、`h1`）の一部は、本番の画面ではまだ試していない**（1Aで使ったのは `stSidebar`・`stStatusWidget`・`h1` とサイドバーのボタン。メイン領域のボタン、`details` 内のメンバー名ボタン、通知カードは未検証）。最初の周の前に `chk` で見つかるかを確かめる。

### 3-2 呼び出し（1遷移 = 1回）

```js
await window.__T0E.run('1')          // ① ホーム→部活を探す
await window.__T0E.run('14', '申込') // ⑭ 通知「見る」（種類を指定。省略は「メッセージ」）

```

## 5. 区切り方・保存・再開

- **約30回の呼び出しごとに会話を区切る**（PM決定）。周の途中でもよい。目安: 区切り1＝周1〜周1.5、…。⑥は10回なので E002 の1区切りで完結する。

- **再開**: 次の区切りの kurosu は、この手順書と結果ファイル（`10-cloud-baseline.md`）の**最後の行**を読み、次の「周・順」から続ける。再開時に必ず行うこと：（1）人間が画面を見ているか確認、（2）`tabs_context_mcp` で計測タブがあるか確認（人間・god が続行を許可したタブだけ使う）、（3）`window.__T0E` が残っているか確認（リロードされていれば 3-1 を再登録）、（4）`chk` と現在の見出しが、次の順の起点と一致するか確認、（5）ログインが切れていたら人間に再ログインを頼む。一致しなければ、人間に報告して止まる。
- 区切りの終わりに、`visibilityState` が `hidden` だった回数を結果ファイルの備考に書く。

## 6. 判定不能・破棄の扱い（SP-81⑤）

- `hidden` で `discard` になった回、`timeout`、`none` は**有効な回に数えない。** 値（取れた分）と回数を結果ファイルの備考に残す。
- 有効な回が5回に満たない遷移（n<5）は**判定不能**とし、合否に使わない。測り直す。**測り直しの範囲（不足分だけ足すか、最初から5回やり直すか）は仕様に書かれていない。** 案：不足分を足して有効5回にそろえる。ただし、破棄した回数と値は集計表の備考に必ず残す（破棄が遅い回に偏ると、残りの中央値が実態より良く見えるため）。**この案は god・PM の確認が要る。**
- 破棄が続く（周の途中で2回以上 `hidden`）ときは、そこで止めて、人間に Chrome を最前面にしてもらってから続ける。1Aの再発を防ぐため。
- 「通知（未読あり）」は、周1の順1の1回だけ。5回そろわないため、別行（参考・n=1）で記録する。判定の対象にするかは未決（テスト設計 5章15）。
- 計測中にアプリがエラー表示や接続切れ（Streamlit の接続エラー）になったら、その回は破棄し、人間に報告して止まる。

## 8. トークンの節約

- スクショ・`read_page`・`get_page_text` は使わない。返り値は1行のテキストだけ。
