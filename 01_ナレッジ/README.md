# ナレッジ運用スキーマ

チームの学びを資産にする。毎回ゼロから調べ直さないための台帳。主担当は書記、記録は全員の責務。

## 構成（二層）

ナレッジは「横断の台帳」と「記事の本体」の二層に分ける。

| 層 | 場所 | 中身 |
|---|---|---|
| 横断の台帳 | `01_ナレッジ/` | `index.md`＝全記事の所在と要点の索引 ／ `log.md`＝還元の記録 ／ この `README.md`＝運用スキーマ |
| 記事の本体 | 原則 `02_プロジェクト/<案件>/ナレッジ/` | 記事の正本（`.md`） |

- 記事を探すときは、まず `index.md` を読む。本体がどこにあっても、`index.md` の「場所」列で辿れる。
- 案件フォルダの正本と閲覧用 HTML の同期ルールは、各案件の `ナレッジ/README.md` に置く（例: [`02_プロジェクト/bukatsu_concierge/ナレッジ/README.md`](../02_プロジェクト/bukatsu_concierge/ナレッジ/README.md)）。

## 置き分けルール

| 知見の種類 | 本体の置き場所 |
|---|---|
| 案件固有の知見 | `02_プロジェクト/<案件>/ナレッジ/` |
| 複数案件で再利用できる汎用の知見 | `01_ナレッジ/` 直下に置いてよい |

- どちらに置いた記事も、`index.md` に必ず登録する。
- 判断に迷うものは、案件フォルダ側を既定とする。
- 既存の記事は今の場所のままとする。`index.md` に載っている記事のうち、HTML のみが本体のもの（`docs/` 配下）と、`実装ガイド/用語集.md` は、案件の `ナレッジ/` 以外に置かれている。所在は `index.md` の「場所」列で示す。

## 記事の形式

`01_ナレッジ/` 直下に置く新しい汎用記事は、ファイル名を kebab-case にし、次の frontmatter を付けることを推奨する。

```
---
title: <何についての知見か>
type: knowledge | source | synthesis
origin: internal | external | mixed   # internal＝自分たちで確かめた
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: []
---
```

相互参照は `[[wikilink]]`。日付は絶対表記。

案件フォルダ側の既存の正本（例: `02_プロジェクト/bukatsu_concierge/ナレッジ/実践ナレッジ.md`）は、日本語のファイル名で frontmatter も無いが、現状のままでよい。このスキーマとの不整合とは扱わない。`type`・`origin`・更新日は `index.md` の列で補う。

## 操作
- **還元**: 案件の学び（詰まり・判断理由・失敗）を記事にする。手順は次の3つ。
  1. 記事の本体を置く（案件フォルダ、または汎用なら `01_ナレッジ/` 直下）。既存記事への追記でもよい。
  2. `index.md` に載せる（新規なら行を足し、追記なら要点と更新日を直す）。
  3. `log.md` に `## [YYYY-MM-DD] 還元 | <タイトル>` を追記する。
- **query**: まず `index.md` を読み、関連記事を辿って答える。
- **lint**: 矛盾・古い記事・孤立ページを点検する。`index.md` に載っていない記事も「孤立」に含める。

## 品質の目安

- 「やって駄目だったこと」も資産。
