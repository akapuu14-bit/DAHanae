# 部活コンシェルジュ 環境セットアップ手順

作成：Terao（バックエンド・DB担当）
対象：あかぷ／だーあさ／はなえ（各自のPCで開発を始めるための手順）
このドキュメントはセットアップ手順のみです。実装コード・実際のキー/パスワードは含みません（プレースホルダのみ）。

## 0. 前提（一次情報）

- 技術構成: Streamlit（Python）／Supabase（PostgreSQL）／Streamlit Community Cloud／GitHub（要件.md N-01〜N-04）
- ディレクトリ構成の案は設計.md 1章、Secrets/設定の扱いは設計.md 6章のとおり
- ダミーデータは社員500名・部活15件、実在社員情報は不使用、seed固定（要件.md N-07/N-08、仕様.md SP-78）

## 1. Python・仮想環境・依存インストール

```bash
# バージョン確認（3.11系を推奨。プロジェクトで別途指定があればそれに従う）
python3 --version

# プロジェクト直下で仮想環境を作成
python3 -m venv .venv
source .venv/bin/activate   # Windowsは .venv\Scripts\activate

# 依存インストール（requirements.txt は各担当の実装と合わせて用意される想定）
pip install -r requirements.txt
```

現時点でrequirements.txtが無い場合は、最低限次のパッケージが必要になる見込みです（設計.md 1章の構成より）。

```
streamlit
supabase
```

## 2. Supabaseプロジェクトの用意

1. https://supabase.com でアカウント作成し、新規プロジェクトを作成する
2. プロジェクトのURLとAPIキー（anon key）を控える（後述のSecretsで使う）
3. SQL Editorで、設計.md 3章のテーブル定義（型・制約・インデックス方針）どおりにテーブルを作成する
   - テーブル一覧（仕様.md 3.1）: employees, employee_interests, activities, clubs, club_members, events, applications, messages, notifications, action_logs（計10テーブル）
   - 実際のCREATE TABLE文は、担当者（データアクセス層の実装者）が用意するスキーマ定義に従うこと（本書では実コードを書かない）

## 3. Secrets（.streamlit/secrets.toml）の設定

設計.md 6章のとおり、接続先・キー・共通パスワードはStreamlit Secretsで管理し、**コミットしない**（要件.md N-04）。

プロジェクト直下に `.streamlit/secrets.toml` を作成し、以下の形式で値を入れる（下記はプレースホルダ。実際の値は各自のSupabaseプロジェクトから取得し、GitやSlack等に貼らないこと）。

```toml
supabase_url = "https://<あなたのプロジェクト>.supabase.co"
supabase_key = "<あなたのanon key>"
common_password = "<チームで共有する共通ログインパスワード>"
```

`.streamlit/secrets.toml` は `.gitignore` で除外されていることを必ず確認する。

```bash
git check-ignore -v .streamlit/secrets.toml
# 何か出力されれば除外設定は有効
```

環境変数での代替（テストやCIなど、Streamlit実行環境の外でSupabaseクライアントを使う場合）:

```bash
export SUPABASE_URL="https://<あなたのプロジェクト>.supabase.co"
export SUPABASE_KEY="<あなたのanon key>"
```

## 4. アプリの起動

```bash
streamlit run app/frontend/app.py
```

ブラウザが自動で開かない場合は、ターミナルに表示されるURL（通常 http://localhost:8501 ）を開く。

## 5. ダミーデータの投入

仕様.md SP-78・要件.md N-07〜N-09のとおり、テストデータの初期化は開発者が自分のPCから実行する開発者用処理とし、アプリ画面にはボタンを置かない。

```bash
python scripts/reset_data.py
```

- 実行すると、すべてのテーブルを空にしてから、社員500名・部活15件のダミーデータを入れ直す（実在社員の情報は使用しない）
- 乱数のseedは固定されており、何度実行しても同じデータになる想定（要件.md N-08）
- **注意**: 公開環境（Streamlit Community Cloud等）に接続した状態で実行すると、申込・メッセージ・操作履歴もすべて消える。実行前に必ずチーム内で声をかける（仕様.md SP-78）

`scripts/reset_data.py` 自体は各担当（実装計画.md ではダミーデータ生成ははなえ担当）が用意するため、本書ではその中身までは書かない。

## 7. よくある詰まりどころ

| 症状 | 想定される原因 | 対処 |
|---|---|---|
| `streamlit run` 時に `ModuleNotFoundError` | 仮想環境が有効化されていない／依存が入っていない | `source .venv/bin/activate` を確認し、`pip install -r requirements.txt` を再実行 |
| 画面に「データを読み込めませんでした。時間をおいて再読み込みしてください」（仕様.md SP-06） | Supabaseの接続情報（URL/キー）が違う、またはSecretsが読めていない | `.streamlit/secrets.toml` の値と、Supabaseプロジェクトの実際のURL/anon keyを見比べる |
| ログインできない（社員IDかパスワードが違います） | ダミーデータ未投入、または`common_password`のSecrets値がチーム共有のものと違う | `python scripts/reset_data.py` を実行済みか確認し、common_passwordをチームに確認する |
| `git status` に `secrets.toml` が出てきてしまう | `.gitignore` にパスが登録されていない、または既に一度コミットしてしまっている | `.gitignore` を確認。既にコミット済みの場合は他のメンバー・運営に相談（秘匿値のコミットは絶対禁止のため、履歴からの削除も含めて対応が必要） |
| `reset_data.py` を実行するたびにデータ件数が変わる | seedが固定されていない実装になっている、または一部処理に乱数依存の非決定的な要素が残っている | 実装側（はなえ担当分）に確認 |
| 日時の表示がずれる（仕様.md SP-07: 「9/26（土）19:00」形式で日本時間表示） | タイムゾーン変換の実装漏れ、またはOS/実行環境のタイムゾーン設定 | DB側はタイムゾーン付きで保存する前提（要件.md N-05）。表示側の変換ロジックを確認 |

## 8. 保留（本書執筆時点で未確定・確認が必要な点）

- `requirements.txt` の正式な内容（バージョン固定を含む）は、実装が進んだ時点で確定する
- `scripts/reset_data.py` の実行に必要な追加パッケージ（乱数生成ライブラリ等）は、実装担当（はなえ）の実装内容に従う
- Supabaseのテーブル作成手順（SQL実行）を1クリックで済ませるマイグレーションの有無は、この方針変更（実装は人間チーム各自で進める）を踏まえて別途チームで決めること
