## 0. 前提（一次情報）

- 技術構成: Streamlit（Python）／Supabase（PostgreSQL）／Streamlit Community Cloud／GitHub（要件.md N-01〜N-04）
- ディレクトリ構成の案は設計.md 1章、Secrets/設定の扱いは設計.md 6章のとおり
- ダミーデータは社員500名・部活15件、実在社員情報は不使用、seed固定（要件.md N-07/N-08、仕様.md SP-78）

## 1. Python・仮想環境・依存インストール

```bash
# バージョン確認（3.11系を推奨。プロジェクトで別途指定があればそれに従う）
python3 --version

# プロジェクト直下で仮想環境を作成
python3 -m venv .venv
source .venv/bin/activate   # Windowsは .venv\Scripts\activate

# 依存インストール（requirements.txt は各担当の実装と合わせて用意される想定）
pip install -r requirements.txt
```

現時点でrequirements.txtが無い場合は、最低限次のパッケージが必要になる見込みです（設計.md 1章の構成より）。

```
streamlit
supabase
```

## 2. Supabaseプロジェクトの用意（PM決定：チームで1プロジェクトを共有）

**Supabaseプロジェクトは個人ごとに作らない。チームで1つの共有プロジェクトを使う。**

> **セキュリティ境界**：現在のMVPは架空データ限定の開発環境としてRLSを無効にする。アプリの`common_password`はSupabase Authではなく、DB側の利用者識別には使えない。外部公開または実データ利用の前に、Issue #45「外部公開前のSupabase Auth＋RLS設計・適用」を完了すること。Issue #45完了前の外部公開・実データ投入は禁止する。

- **新規作成は1回だけ、Data/BE担当（だーあさ）が行う。**
  1. https://supabase.com でアカウント作成し、新規プロジェクトを作成する
  2. SQL Editorで、設計.md 3章のテーブル定義（型・制約・インデックス方針）どおりにテーブルを作成する
     - テーブル一覧（仕様.md 3.1）: employees, employee_interests, activities, clubs, club_members, events, applications, messages, notifications, action_logs（計10テーブル）
     - 実際のCREATE TABLE文は、担当者（データアクセス層の実装者）が用意するスキーマ定義に従うこと（本書では実コードを書かない）
  3. プロジェクトのURLとAPIキー（anon key）を控え、チームに共有する（Slack等の非公開チャンネルで。GitHubには絶対に貼らない）
- **他メンバー（あかぷ／はなえ）は、自分でプロジェクトを新規作成しない。** だーあさから共有された接続URL/anon keyを、次章の`.streamlit/secrets.toml`にそのまま設定するだけでよい

> 全員が同じデータベースに接続する構成のため、ダミーデータの再投入（5章）やテーブル変更は、
> 実行前に必ずチーム内で声をかけること（他メンバーの作業中データも消える・変わる）。

## 3. Secrets（.streamlit/secrets.toml）の設定

設計.md 6章のとおり、接続先・キー・共通パスワードはStreamlit Secretsで管理し、**コミットしない**（要件.md N-04）。

**2章のとおりSupabaseプロジェクトはチームで1つの共有なので、ここで入れる`supabase_url`/`supabase_key`は
自分で新規発行する値ではなく、だーあさから共有された値をそのまま使う。**

プロジェクト直下に `.streamlit/secrets.toml` を作成し、以下の形式で値を入れる（下記はプレースホルダ。
実際の値は共有された内容を使い、GitHubに貼らないこと。Slack等の非公開チャンネルでの共有はOK）。

```toml
supabase_url = "https://<チーム共有プロジェクト>.supabase.co"
supabase_key = "<チーム共有のanon key>"
common_password = "<チームで共有する共通ログインパスワード>"
```

`.streamlit/secrets.toml` は `.gitignore` で除外されていることを必ず確認する。

```bash
git check-ignore -v .streamlit/secrets.toml
# 何か出力されれば除外設定は有効
```

環境変数での代替（テストやCIなど、Streamlit実行環境の外でSupabaseクライアントを使う場合）:

```bash
export SUPABASE_URL="https://<チーム共有プロジェクト>.supabase.co"
export SUPABASE_KEY="<チーム共有のanon key>"
```

## 4. アプリの起動


## 5. ダミーデータの投入

仕様.md SP-78・要件.md N-07〜N-09のとおり、テストデータの初期化は開発者が自分のPCから実行する開発者用処理とし、アプリ画面にはボタンを置かない。

```bash
python scripts/reset_data.py
```

- 実行すると、すべてのテーブルを空にしてから、社員500名・部活15件のダミーデータを入れ直す（実在社員の情報は使用しない）
- 乱数のseedは固定されており、何度実行しても同じデータになる想定（要件.md N-08）
- **注意**: 公開環境（Streamlit Community Cloud等）に接続した状態で実行すると、申込・メッセージ・操作履歴もすべて消える。実行前に必ずチーム内で声をかける（仕様.md SP-78）

`scripts/reset_data.py` 自体は各担当（実装計画.md ではダミーデータ生成ははなえ担当）が用意するため、本書ではその中身までは書かない。

## 7. よくある詰まりどころ

| 症状 | 想定される原因 | 対処 |
|---|---|---|
| `streamlit run` 時に `ModuleNotFoundError` | 仮想環境が有効化されていない／依存が入っていない | `source .venv/bin/activate` を確認し、`pip install -r requirements.txt` を再実行 |
| `ModuleNotFoundError: No module named 'supabase'`（仮想環境を有効化しても出る） | `streamlit` コマンドが、依存の入っていない別のPython（例: `/Library/Frameworks/Python.framework` 系）をPATHの順で掴んでいる | 下の「7.1 起動に使われるPythonの取り違え」で確認し、依存が入っているPythonを名指しで起動するか、`streamlit` が指すPythonへ依存を入れ直す |
| 起動はするが secrets が見つからない（`app/frontend/.streamlit/` を探している） | `cd app/frontend` してから `streamlit run app.py` で起動している。secrets はリポジトリ直下の `.streamlit/secrets.toml` にある | 必ずリポジトリ直下から `streamlit run app/frontend/app.py` で起動する（3章・4章と同じ） |
| 画面に「データを読み込めませんでした。時間をおいて再読み込みしてください」（仕様.md SP-06） | Supabaseの接続情報（URL/キー）が違う、またはSecretsが読めていない | `.streamlit/secrets.toml` の値が、だーあさから共有された共有プロジェクトのURL/anon keyと一致しているか見比べる（自分で別プロジェクトを作っていないか確認） |
| ログインできない（社員IDかパスワードが違います） | ダミーデータ未投入、または`common_password`のSecrets値がチーム共有のものと違う | `python scripts/reset_data.py` を実行済みか確認し、common_passwordをチームに確認する |
| `git status` に `secrets.toml` が出てきてしまう | `.gitignore` にパスが登録されていない、または既に一度コミットしてしまっている | `.gitignore` を確認。既にコミット済みの場合は他のメンバー・運営に相談（秘匿値のコミットは絶対禁止のため、履歴からの削除も含めて対応が必要） |
| `reset_data.py` を実行するたびにデータ件数が変わる | seedが固定されていない実装になっている、または一部処理に乱数依存の非決定的な要素が残っている | 実装側（はなえ担当分）に確認 |
| 日時の表示がずれる（仕様.md SP-07: 「9/26（土）19:00」形式で日本時間表示） | タイムゾーン変換の実装漏れ、またはOS/実行環境のタイムゾーン設定 | DB側はタイムゾーン付きで保存する前提（要件.md N-05）。表示側の変換ロジックを確認 |

### 7.1 起動に使われるPythonの取り違え（`No module named 'supabase'`）

`pip install` した先のPythonと、`streamlit` コマンドが使うPythonが別だと起きる。次の順で確認する（secrets の中身は表示しない）。

```bash
which -a streamlit                                     # PATH上の streamlit を全部表示
head -1 "$(which streamlit)"                           # 先頭の streamlit が使う Python（shebang）
python -c 'import supabase,sys;print(sys.executable)'  # 依存が入っている Python の場所
```

`streamlit` の shebang と、`import supabase` が通る Python が違えば原因。対処はどちらか。

```bash
# A. 依存が入っているPythonを名指しで起動（例。自分の環境のパスに置き換える）
/opt/anaconda3/bin/python -m streamlit run app/frontend/app.py

# B. streamlit が指すPythonへ依存を入れる（壊れかけのパッケージが残る場合に備え --force-reinstall）
python -m pip install --user --force-reinstall -r requirements.txt
```

起動は、どちらの場合もリポジトリ直下から行う（`cd app/frontend` しない）。
