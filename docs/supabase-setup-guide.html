02 / 07　用語を理解する

Supabaseと3種類の「パスワード／キー」

Supabase

アプリのデータを保存・取得するクラウドサービスです。今回はチームで1つのプロジェクトを共有します。

Anon key

アプリがSupabaseへ接続するための公開用キーです。今回はこれを使用します。

使用する

Common password

部活コンシェルジュのデモログイン用パスワードです。SupabaseのDBパスワードとは別物です。

アプリ専用
使用・共有しないもの：service_role / secretキー、Supabase作成時のDatabase password。

この資料では実値を非表示にしています： <ANON_KEY> <COMMON_PASSWORD>

2
03 / 07　なぜSecretsを使うのか

共有する「雛形」と、共有しない「実値」を分ける

secrets.toml.example

項目名だけを示す見本です。秘密の値は入れず、GitHubでチーム共有します。

コミットOK

secrets.toml

各自のPCで実値を入れるファイルです。Gitの管理対象外にして、GitHubへ送信しません。

コミット禁止
たとえると：exampleは「空欄の申込用紙」、secrets.tomlは「個人情報を記入した申込用紙」です。
# 公開用の雛形（値は伏せる）
supabase_url = "https://<PROJECT_REF>.supabase.co"
supabase_key = "<ANON_KEY>"
common_password = "<COMMON_PASSWORD>"

04 / 07　雛形担当者の作業

T-B02：チームがコピーできる雛形を準備する

担当：はなえさん ファイル所有境界に従い、担当者が作成・マージします。

  1. .streamlit/secrets.toml.exampleを作成する
  2. キー名とダミー値だけを記載する
  3. .streamlit/secrets.tomlが.gitignore対象であることを確認する
  4. PRをマージし、チームへ準備完了を連絡する
git check-ignore -v .streamlit/secrets.toml
git status --short
重要：雛形へanon keyやCommon passwordの実値を記載しない。
4
05 / 07　各メンバーの作業

最新化 → コピー → DMの値を設定

1. 最新の雛形を取得

git pull

2. 雛形を各自の秘密ファイルへコピー

cp .streamlit/secrets.toml.example .streamlit/secrets.toml

3. secrets.tomlをVS Codeで開き、DMで受け取った値を設定

supabase_url = "https://<PROJECT_REF>.supabase.co"
supabase_key = "<DMで受け取ったANON_KEY>"
common_password = "<DMで受け取ったCOMMON_PASSWORD>"
5
06 / 07　事故を防ぐ最終確認

コミット前に必ず2つ確認する

git check-ignore -v .streamlit/secrets.toml
git status --short
正常：git check-ignoreで.gitignoreの該当行が表示され、git statusの変更一覧にsecrets.tomlが出ない。
異常：secrets.tomlが変更一覧に出たら、絶対にコミットしない。作業を止めてチームへ連絡する。
  • 新しいSupabaseプロジェクトを個別に作っていない
  • service_role / secretキーを使用していない
  • Pythonコードへキーやパスワードを直接書いていない
  • GitHub、Issue、PR、公開チャンネルへ実値を貼っていない

07 / 07　まとめ

覚えておくポイントは4つだけ

1. DBは1つ

全員がチーム共有のSupabaseプロジェクトを使う。

2. 実値はDM

接続情報とCommon passwordは公開場所へ貼らない。

3. exampleは見本

GitHubで共有するが、実際の秘密情報は入れない。

4. secretsは各自のPCだけ

Git管理対象外になっていることを必ず確認する。

完了条件：設定とGit除外の確認が終わったら、チームのDMへリアクションしてください。

不明点があれば、そのまま進めず画面共有で一緒に確認しましょう。
