## 1. これは何？（30秒で概要）

**「GitHubにタスクを置いて、コードのPRとつなぐだけで、進捗が自動で最新化される」仕組み**です。

- **タスク** = GitHub の **Issue**（例:「S04 部活詳細画面を作る」）
- **作業** = ブランチを切って実装 → **PR** を出す
- **完了** = PR本文に `Closes #12` と書いてマージ → **Issueが自動でクローズ**
- **見える化** = クローズ/オープンの状況を集計した **HTMLダッシュボード** が、イベントのたびに自動で更新され、GitHub Pages のURLで見られる

👉 **進捗更新のための「報告作業」はほぼゼロ。** 普段どおり Issue を立てて PR を出すだけで、ダッシュボードが勝手に最新になります。

## 2. 登場するもの

| もの | 役割 | どこ |
|---|---|---|
| **Issue** | 1タスク。担当者・ラベル・Milestoneを持つ | GitHubの Issues タブ |
| **Milestone** | 期日の節目。R-48の3節（〜9/29 / 〜10/2 / 10/7-12）。進捗バーが自動表示 | Issues → Milestones |
| **Label** | 領域の色分け（`area:be` `area:ui` `area:pdm`）と種別・優先度 | Issue作成時に付与 |
| **PR** | コードの変更。`Closes #番号` でIssueと連動 | Pull requests タブ |
| **ダッシュボード** | 担当者別の完了/未完了・Milestone進捗・直近マージPRを自動集計したHTML | GitHub Pages の公開URL |

**関連ファイル**
- `.github/workflows/dashboard.yml` … 自動更新の仕掛け（触らなくてOK）
- `scripts/gen_dashboard.py` … ダッシュボードHTMLの生成（触らなくてOK）
- `scripts/setup_github.sh` … Label/Milestone/Issueの初期作成（最初に1回）

## 3. 毎日の使い方（役割別・ここだけ読めばOK）

### 👤 実装する人（だーあさ / あかぷ / はなえ）

1. **今日やるタスクの Issue を開く**（無ければ新規作成。タイトル＋ざっくり内容＋ラベル＋担当を自分に）
2. **ブランチを切る**：`feature/<領域>-<機能>`（例 `feature/ui-club-detail`）
3. 実装したら **PRを出す**。PR本文に必ず1行：
   ```
   Closes #12
   ```
   （#12 はそのタスクのIssue番号。これで**マージ時にIssueが自動クローズ**）
4. PRには「対応SP/F」「テスト設計の該当S/I番号」「単体テスト結果」を書く（証拠を残す）
5. レビューOK → マージ → **ダッシュボードが自動更新**。以上っ！

> ✅ ポイント：**進捗を別途どこかに書き込む必要はありません。** Issueを閉じる＝進捗が進む、が自動で反映されます。

### 🔍 レビュー/PR承認する人（はなえ）

- PRを見て承認。**自分が書いたコードは他の人（あかぷ/だーあさ、設計面は takahiro）にレビューしてもらう**（自己承認は避ける）。
- マージ時に `Closes #` が入っているか確認（入っていれば自動クローズされる）。

### 📊 進捗をフォローする人（PM・全員）

- **ダッシュボードのURLを開くだけ**。担当者別の完了/未完了、Milestoneの進捗バー、直近マージPRが常に最新で見えます。
- 定例は「昨日やった/今日やる/詰まり」だけの短い同期でOK。数字はダッシュボードが持っているので、報告資料づくりは不要。

## 4. 「ほぼ工数ゼロ」で回る理由

| やりたいこと | 誰がやる | 手間 |
|---|---|---|
| 進捗を最新にする | 自動（PRマージがトリガー） | **0**（普段の開発で完結） |
| 担当別の状況を見る | 見る人 | URLを開くだけ |
| 期日ごとの達成度を見る | 見る人 | Milestoneバーを見るだけ |
| 日次の定点更新 | 自動（毎日1回スケジュール実行） | **0** |

手で更新するのは「Issueを立てる」「PRに `Closes #` を書く」の2つだけ。あとは全部自動です。

## 6. 困ったら（FAQ）

- **Q. Issueを閉じ忘れた** → PRに `Closes #番号` を入れ忘れただけ。Issueを手で閉じてもダッシュボードは次の更新で反映されます。
- **Q. ダッシュボードが更新されない** → mainにワークフローが載っているか、Pagesが有効か、Actionsが成功しているか（Actionsタブ）を確認。
- **Q. 担当が表示されない** → その人のIssueに assignee が設定されているか確認（ダッシュボードは実際のassigneeで自動集計）。
- **Q. すぐ最新にしたい** → Actionsタブから `dashboard` を手動実行（workflow_dispatch）。
